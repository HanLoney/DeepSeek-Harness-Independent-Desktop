# Agent Note: Desktop task widget over the loopback session stream

Status: implemented

[English](2026-09-23-desktop-task-widget.md) | 中文

## Problem

桌面应用只在主窗口里显示会话进度，而主窗口经常被其他工作盖住。用户想知道一个长任务是否还在跑、卡在哪个工具、待办清单推进到哪一步、消耗了多少 token，都得切换窗口去读对话。桌面进程本身不汇报其中任何一项。

上游 `dsh-whale-widget` 项目解决了“扫一眼就能看到”的那一半——一只浮在桌面上的鲸鱼——但它是一个 Web 客户端插件，有自己的一套余额记账用途，并且要向 Harness 客户端清单注册。原样采纳会引入没人要求的记账功能，还会把悬浮窗和 Web bundle 的构建绑在一起。

## Decision

`apps/desktop/widget/` 是一个自包含的悬浮窗：一个无边框、始终置顶的 Electron `BrowserWindow`，汇报当前会话的回合阶段、正在执行的工具、待办进度、目标轮次，以及 token 与耗时统计。

挂件不改动 `packages/` 下的任何代码。它读取主窗口已在使用的同一个回环 `dsh web` 后端，走既有的 `/api/events.mux` WebSocket 流，外加一次 `session.list` 调用取基线。

它贡献的唯一一个插件——下面描述的设置面板——安装进用户自己的 profile，而不是仓库，因此它既不向工作区新增软件包，也不向任何随包发布的 bundle 新增配置行。

### 为什么由桌面端消费客户端 API，而不是写 host 插件

host 插件本可以在进程内归约进度并通过 IPC 推送。之所以否决，是因为那会把挂件放进 harness 的软件包图谱：一个新包、一行 bundle 配置、一个 tsconfig 引用，以及一条客户端插件清单条目——四处注册面必须一起改，漏掉任何一处都会在更靠后的、各不相同的位置报错。用户要求“删掉一个目录就能拔除这个功能”，这与那种耦合不相容。

消费客户端 API 让挂件待在一条已经存在、且已被测试过的边界上。代价是挂件看到的就是浏览器客户端看到的东西：它必须自行订阅并归约，而不能直接读派生状态；同时它依赖部署所挂载的那些插件提供的会话投影词汇表。

设置面板是这条边界的那条例外：它确实是一个客户端插件，但由桌面宿主在运行时安装进 `$DSH_HOME/profiles/`，而不是声明在仓库的组合配置里。`packages/` 里没有任何地方提到它。

### 真实数据逼出来的归约规则

有两条规则并不显然，而且都是靠归约一个真实的 2534 事件会话发现的，不是靠审阅代码看出来的：

**投影帧是整值，不是增量。** `session/projection` 携带某个键的完整当前值，且以后写覆盖先写，所以归约就是赋值。挂件最初的实现累加 token 字段，随着帧陆续到达，最终会报出真实值的若干倍。

**token 总数只来自 `tokenUsage` 投影。** `assistant/message` 和 `tokenUsage` 投影描述的是同一批 token，而投影覆盖整个日志。两处都归约会重复计数。挂件现在只从每步 usage 里读 `reasoningTokens`，那是投影不携带的字段。

还有第三条值得记录的命名陷阱：投影键是所属接缝自己的词汇表。挂件最初查找 `sessionTitle`，而会话接缝发布的是 `title`，于是它静默地什么都不显示。未知键被忽略而不是被近似——对于可选的部署来说这是正确行为，但也意味着写错键名会静默失败；`widget/README.md` 把这条列为新增指标时首先要核对的事项。

### 渲染层自己做主的决定

渲染层的展示决定都放在 `view.mjs` 里，它没有 DOM，并由 `apps/desktop/tests/widget-view.test.mjs` 覆盖。之所以这样拆，是因为这些决定正是挂件真正出错的地方，而没有一个是靠盯着窗口能看出来的：

- **跨会话比较。** 状态迁移跟踪器比较的是相邻两次轮询的计数，所以切换会话时必须重置。不重置的话，挂件会把另一次运行的已完成待办当成这次会话的进度，并播放用户根本没挣到的完成音效。空闲计时也要一起重置，因为继承它会让新会话的气泡立刻收起。
- **哨兵值。** 空闲计时用 `null` 而不是 `0`：毫秒时间戳本来就可能是零，而哨兵值与真实数据共用取值会让“从未空闲”和“在纪元时刻空闲”无法区分。
- **重复音效。** 一个回合结束时若清单恰好已完成，就同时满足回合条件与待办条件，导致一个事件播放两次完成音。
- **未知词汇。** 无法识别的阶段或结果会原样显示，而不是替换成默认值，因为猜出来的标签会把失败的回合说成成功。

### 窗口行为

窗口比贴图更大，且默认穿透点击；渲染层对鲸鱼和气泡做矩形命中测试，并通过 preload 桥汇报指针状态。没有这一步，透明的边距会吞掉本该落到下方桌面的点击。

窗口位置保存在桌面配置旁，下次启动时恢复，并会被拉回已连接显示器的工作区内，而不只是被拒绝：直接拒绝一个大体仍然有效的位置，会因为几个像素悬在边缘外就丢掉那个角落。保存发生在移动时与关闭时各一次，所以拖拽后立刻退出也能保留位置。

渲染层轮询 `GET /widget/state` 时带单次飞行保护。没有它的话，比轮询间隔更慢的后端会让每个 tick 累积一个请求，而每一次都在画已经被下一次取代的快照。

该路由以 `text/javascript` 提供 `.mjs`。以 `application/octet-stream` 提供的模块会在代码执行前就被浏览器拒绝，窗口直接变白——拆分后的第一次实机运行就抓到了这一点，现在有测试断言每个模块的内容类型。

音效开关是双击气泡，因为单击会在普通拖拽过程中把挂件静音。

### 需要菜单的命令，以及为什么拖拽不用 CSS 区域

窗口无边框且不进任务栏，所以没有菜单就没有任何办法隐藏或关闭它。在任意绘制区域上右键会给出隐藏、静音、退出；托盘图标上也有同样三项。

命中区域是"鲸鱼"与"气泡"两个矩形在每次事件上重算的并集，而不是固定的框，也不再是逐节点判定。最初的实现逐个节点判定，结果在两者之间那道缝隙里右键——仍在窗口内、视觉上属于挂件——会穿透到透明边距。

拖拽从 `-webkit-app-region: drag` 改成了由 preload 桥按指针位移驱动。基于区域的拖拽与右键菜单无法共存：Windows 会把拖动区域当作标题栏，并在页面看到之前就吃掉其中的右键，于是菜单除鲸鱼之外到处都能弹出。这在 devtools 控制台里完全看不出来，只有在运行的窗口上真按一次右键才会暴露。在子元素上写 `-webkit-app-region: no-drag` **并不能**把它从祖先的区域里挖出来——这个值必须写在区域本身。

窗口同时是穿透点击打开的，而渲染层的交互标记初始为 `false` 与之对应。若初始为 `true`，第一次悬停会变成空操作，窗口会一直保持穿透，直到指针离开再回来。

### 设置开关

启用开关在主窗口的设置面板里。切换后挂件会在一两秒内启停，既不用重启应用，也不用重启后端。

那个面板是一个客户端插件，而客户端插件的浏览器半身只通过一个 loader 行被发现，该行的 `name` 必须能解析成一个包：client-modules 扫描器会读 `<name>/package.json`，并服务 `exports["./client"]`。所以面板需要把包复制进 profile 自己的 `node_modules`，再加一行指向它，这两件事都由 `widget/install.mjs` 在后端启动之前完成——后端只在启动过程中才会看到这个插件。那一行被标记注释围起来，手改过的 profile 会保留它的每一行；`uninstall` 则把 patch 文件逐字节还原。

有两条放置规则是承重的。包进 profile 自己的 `node_modules`，绝不进同级的 `profiles/node_modules`：后者是 harness 的扁平模块回退层，为安装依赖闭包里的每个包放一个符号链接，它的修复步骤遇到同名真实目录会直接抛错——不在闭包里的名字放在那里只是碰巧安全。而 patch 文件不存在时，要用 harness 自己的模板去播种，而不是写一个空列表，因为 harness 只在文件不存在时才写那个模板，抢先创建会永久剥夺该 profile 的模板头。

有三处细节是承重的，而且每一处都会让整个插件树失败，而不只是面板：

- bundle 以**包名**注册自己。用 loader 行的 `id` 注册会以 "loaded without registering" 失败。
- 那一行需要显式的 `config: {}`。loader 会拿插件的 schema 校验它，而缺失的 config 不等于默认值。
- 设置 schema 是 schemastery，不是 zod，且没有 `.shape`；字段名来自 `.dict`。

面板不使用通用的设置 RPC。`dsh-host-apiproxy` 把那个 RPC 挡在一个插件无法扩展的命名空间白名单后面，因此插件注册自己的 `/desktop-widget/config` 路由，并写入同一个 settings 服务。文档、它的 schema，以及桌面宿主对它的视图都是共享的，只有传输方式不同。

启动时以存储的设置为准，本地 `widget.enabled` 配置只在面板未安装的部署里作为回退。监视器只对存储值的**变化**作出反应，因此从托盘或菜单手动退出后会保持退出，而不会被下一次轮询撤销。

### 气泡属于立绘，不属于挂件

工作态立绘自带一个思路气泡。挂件内容定位在它内部，是透明的居中文字而非自带背景的面板——带背景的面板等于在画好的气泡上再摞一个气泡，观感是贴上去的。文字配色因此以气泡的白色内区为准；所有运行中的阶段都映射到这张带气泡的立绘，因为在气泡可见时使用只有脸的立绘，会让文字飘在鲸鱼旁边而非气泡里。

这给 `widget.css` 带来两条别处无人保证的约束：气泡的 `z-index` 必须高于立绘，否则位于其后的立绘会把它盖住；`[hidden]` 需要 `!important`，因为各隐藏元素自身 class 设定的 `display` 优先级高于用户代理的 `[hidden]` 规则。两种失效都不可见——渲染层设置属性、属性也确实写上了，屏幕上却毫无变化——因此由 `widget.test.mjs` 断言。

### 解耦

这个功能是一个目录加几处接触点：`config.mjs` 里的 `widget` 分组、`main.mjs` 里的三行 import 与 `widgetOptions`/`readWidgetSettings`/`watchWidgetSettings`/`startWidget` 块、打包 `files` 清单里的 `widget` 条目，以及它的测试文件。`widget/README.md` 列出了确切的拔除步骤，其中包含应用已经运行过时留在 `$DSH_HOME/profiles/` 里的两件运行时产物。删掉这个目录会连同所有素材一起移除。

最后一点在许可上很重要：上游的美术素材与音效并非 MIT 许可，`widget/PROVENANCE.md` 记录了它们不得随开源发布一起分发。

## Alternatives considered

**照原样采纳 `dsh-whale-widget` 作为 Web 客户端插件。** 它已经画出带拖拽、吸附和按压音效的鲸鱼浮层，presentation 部分基本可以白拿。否决原因是它的用途是余额记账而非任务进度，而且 Web 客户端插件活在浏览器页面里——它会浮在 Harness 窗口上方，而不是桌面上，主窗口隐藏时就完全看不见。最终复用了素材，没有复用架构。

**写一个在进程内归约进度的 host 插件。** 理由见上：它把功能放进 harness 的软件包图谱，废掉了目录级拔除。

**用 SSE 或普通 GET 通道做实时更新。** 对 `/api/events.mux` 发 GET 会返回 426 upgrade required——唯一的实时载体是 WebSocket 升级，或 fetch handler 里的 POST 加 SSE 路径。否决原因是走普通 HTTP 面就得往 harness 里新增端点，而这正是本设计要避开的耦合。

**让挂件窗口自己直连后端的 WebSocket。** 这样可以去掉宿主的归约层。否决原因是归约就会变成每个窗口各跑一份，刷新即丢失；而且挂件窗口得自带重连与基线逻辑，却没地方安放。

## Consequences

挂件是流的一个视图，因此它只显示已挂载插件所投影的内容。在没有 todo 或 goal 插件的部署里，气泡对应部分为空而不是错误——这是预期的降级方式，也是未知投影键被忽略的原因。

进度按会话汇报，而挂件只显示一个：阶段非 idle 的最新会话，回退到最新的会话。并行跑多个会话的用户看到的是最近活跃的那个，而不是列表。

没有后台作业面板。用户选择了回合状态、待办进度、统计数字和目标进度；作业在选项里提供但被明确排除，因此挂件没有对应的代码路径。

宿主为每个会话保留一条记录，不做淘汰。会话会持续累积直到挂件窗口关闭，上限取决于单次桌面运行触及多少个会话。

上游素材不带许可证，这使该功能在素材被替换或取得授权前仅限于个人使用。`widget/PROVENANCE.md` 写明了这条边界。

## Testing

`apps/desktop/tests/widget.test.mjs` 独立覆盖归约逻辑：阶段映射、工具生命周期（包括 `turn/end` 时的清理）、回合结果记录、整值投影规则、快照投影，以及 HTTP 面（包括拒绝路径穿越）。

它还会把 `main.mjs` 与 `window.mjs` 对照，检查 `widgetOptions` 传入了每个被读取的选项，并对照 `renderer.js` 与 `index.html` 检查元素 id，以及 `renderer.js`、`widget.css`、`index.html` 里引用的每个素材文件都确实存在。这三项各自都出过错——漏传的 preload 路径、写错的投影键名、服务成 octet-stream 的模块——而且都只能在实机运行时静默失败。

`apps/desktop/tests/widget-settings.test.mjs` 针对一个临时 harness home 覆盖 profile 接线：包与配置行被写入、模板里的空 `[]` 是被替换而不是与第二个 YAML 文档并存、第二次安装报告无变化、`uninstall` 逐字节还原文件、手写的配置行得以保留、bundle 的 loader id 就是包名，以及 `DSH_HOME` 的解析与所生成后端一致。每条断言都对应一次实机观察到的失败或 loader 自身的报错——第二个 YAML 文档、缺失的 `config: {}`、写错的 bundle id，三者在成为测试之前都让后端启动失败过。

此外还用真实的 `dsh web` 后端验证过：36 个会话的 `session.list` 基线、一次真实的 `/api/events.mux` 订阅，以及对一个真实 2534 事件会话的归约，结果与 `sessionStats` 投影一致。进行中与已完成两种界面都用真实会话数据渲染过。

在 Electron 下也实测过：挂件对着一个真实后端启动，报告出按预期尺寸创建的窗口、加载完成的鲸鱼图片、存在的 preload 桥、可用的 `Audio` 构造器，以及从后端状态路由读到的 22 个会话，随后干净关闭。那个选项一致性测试之所以存在，是因为只有第一次实机运行才能发现漏传的 `preloadPath`：当时其他所有检查都通过，而窗口会永久处于点击穿透状态。
